What ANZSIC Classifies

The Australian and New Zealand Standard Industrial Classification codes a business by the productive activity it carries out — not the customer it serves, and not its products as such.

✓Own activityThe classifying variable: similar inputs, similar transformation processes, similar outputs.
½ProductsOutputs are one leg of the production function, but a product classification is a different instrument. ANZSIC codes producers.
✗Customer / marketNever the criterion. Two businesses doing the same work share a class regardless of clientele.

The supply-side framework

ANZSIC 2006 was built on explicitly supply-side industry definitions. The grouping logic is the production function, not the demand side:

The conceptual framework adopted for the development of ANZSIC 2006 uses supply-side based industry definitions and groupings. … business units in a particular class will use similar inputs and apply similar transformation processes to produce similar outputs.

verified 3–0ABS · Nature and objectives

One practical consequence: the same word can point at different classes when the production context differs — the class scope notes carry those qualifiers, so titles alone are never enough to code from.

One unit, one code, by predominant activity

Real businesses do many things. ANZSIC forces a single class anyway, and openly acknowledges the tension:

Each unit has to be classified uniquely to one class so that only those units with the same predominant activities are brought together to form a class. … It is common for a business unit to engage in a range of activities wider than those designated as belonging to a particular class.

verified 3–0ABS · Nature and objectives

Mixed evidence about a genuinely mixed business is therefore not a contradiction to resolve. The question is which activity predominates, not which is exclusive.

Predominance is measured by value added — down a proxy ladder

The measuring stick is value added: the activity contributing the most determines the code. Because value added is rarely observable, the ABS itself falls back through proxies in a stated order of preference — with an explicit caution that they can mislead:

RULEValue addedThe activity with the highest value added is the predominant activity.
P1Sales of goods and servicesRevenue mix — the first substitute when value added is unavailable.
P2Wages and salaries
P3Number of employees

The activity with the highest value added is the predominant activity. … sales of goods and services; wages and salaries; or number of employees … Care needs to be taken with the use of these proxy measures.

verified 3–0ABS · MethodsANZSIC 1292.0 §4.5–4.6

This ladder is why outside-in classification is defensible at all: official coding is already a proxy chain, and website text, directory categories, and trading names extend the same chain further from the books. It is also why a business name loses to activity evidence — a name may describe a former activity or none at all, while the revenue sits elsewhere.

Top-down through the hierarchy

Multi-activity units are assigned division first, then successively subdivision, group, and class verified 3–0 — the ABS, Stats NZ and ISIC all prefer this because it keeps higher-level aggregates consistent.

Division A–S one letter — assigned first Subdivision 73 two digits Group 731 three digits Class 7313 four digits — assigned last, needs the most evidence

An inference pipeline that reports division and subdivision, and withholds the 4-digit class without strong evidence, is mirroring the standard’s own logic — not being timid.

Vertical integration

A unit performing successive production stages is coded by whichever stage adds more value. Where that cannot be assessed, the unit is classified to the activity which represents the last or final stage of production — the final-stage rule is the tiebreak, per the same ABS Methods page verified 2–0. Expect vertically integrated businesses to legitimately resemble several divisions at once.

Ownership is not a criterion

The Division O scope notes state the rule in all three directions:

Government ownership is not a criterion for classification to this industry division.

Government units producing ‘private sector like’ goods and services are classified to the same industry as private sector units engaged in similar activities.

Private sector units engaged in public administration or military defence are classified to the Public Administration and Safety Division.

fetched verbatimABS · Division O scope notes

Even the “government exception” is an activity rule: public administration is itself an activity, and a private contractor performing it lands in Division O too. An entity-type gate in a pipeline is therefore a heuristic shortcut — it works because certain entity types reliably imply public-administration activity. That is exactly why government-owned commercial entities must fall through the gate to be coded on what they do, and why the inverse case — a private firm performing public administration — can never be caught by entity type.

The unit is the producer, not the legal entity

ANZSIC is applied to producing units — the Type of Activity Unit in Australia, the Kind of Activity Unit in New Zealand: “Industries are formed by grouping business units that are mainly engaged in undertaking similar economic activities” (ABS, Units of classification — fetched verbatim). The same page anchors ANZSIC internationally: the 1993 SNA recommends grouping producing units by principal activity according to ISIC.

A customer record keyed to an ABN is a legal entity, not a producing unit. For single-activity small businesses the distinction is invisible; for conglomerates it is why one code per ABN can be honestly wrong — and one more reason abstention is a valid output.
